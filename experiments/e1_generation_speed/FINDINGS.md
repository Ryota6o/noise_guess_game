RTX 6000 Ada(48.5GB、driver 580.178.04) / torch 2.11.0+cu128 / diffusers 0.41.0.dev0 /
transformers 5.20.0 / `Tongyi-MAI/Z-Image-Turbo` bf16 / プロンプト `A dog chases a cat` /

| 解像度 | steps=8 | steps=9 | 1ステップあたり |
|---|---|---|---|

試行間のばらつきは極めて小さい(512px で 1.07〜1.08s)。再現性は問題ない。

## 分かったこと

### 1. NFE は `num_inference_steps` と同数(計画書の記述の訂正)

計画書 §3.1 は「公式サンプルは `num_inference_steps=9` だが実際のモデル評価は8回、
表示できるフレームは最大8枚」と書いていた(HF モデルカードの記述に由来)。

transformer の forward を hook で数えたところ、**steps=8 で NFE 8、steps=9 で NFE 9**。
全解像度で一貫していた。diffusers の `ZImagePipeline` では、ステップ数と評価回数が 1:1 。

**M1 への影響**: 取れる x0 予測の枚数は8枚に縛られない。steps を増やせば増える。
512px なら1ステップ 0.144 秒なので、例えば 12 ステップでも約 1.7 秒で、予算内に収まる。

ただし **Z-Image-Turbo は8ステップ前後に蒸留されたモデル**なので、ステップを増やしても
品質が上がるとは限らず、むしろ崩れる可能性がある。これは**仮説であって未検証**。
M1 で x0 予測の系列を見て、8ステップで「浮かび上がる」変化が足りない場合の選択肢として扱う。

### 2. 時間はほぼノイズ除去。テキストエンコードは無視できる

| 解像度 | テキストエンコード | ノイズ除去 | VAEデコード |
|---|---|---|---|
| 512 | 0.04s | 1.15s | 0.04s |
| 768 | 0.04s | 2.53s | 0.10s |
| 1024 | 0.04s | 4.65s | 0.17s |

テキストエンコード(Qwen3 4B)は解像度によらず **0.04 秒で一定**。3語の短文では、
ここが予算を食う心配はない。計画書 §4.4 の「最も重いのは VLM や LLM の呼び出しになる
可能性がある」という懸念のうち、**テキストエンコーダについては否定された**。
解像度とステップ数が、生成時間のほぼ唯一のつまみ。

### 3. ピーク VRAM は 20〜22GB(報告値の16GBより多い)

| 解像度 | ピーク VRAM |
|---|---|
| 512 | 20.4GB |
| 768 | 21.1GB |
| 1024 | 22.2GB |

計画書 §3.1 の「必要なVRAMは16GB前後(BF16)」は報告値で、実測は 20GB 超。
48GB のうち **残りは約26GB**。CLIP・VLM・ダミー生成用LLM を同居させる余地はあるが、
16GB 前提で見積もると足りなくなる。解像度による増分は小さい(512→1024 で +1.8GB)。

### 4. 報告値はこの環境に移植できない

計画書にある「RTX 4090 で1024×1024を約2.3秒」に対し、**この環境では 4.69 秒**(約2倍)。
RTX 6000 Ada は電力枠 300W で 4090 の 450W より低く、妥当な差ではある。
いずれにせよ**報告値をそのまま予算の根拠に使ってはいけない**ことが確認できた。

## 予算に対する判断

1ターンの予算は「生成 + 事前チェックで5秒以内」(RULES.md §2.1)。生成だけの実測は次の通り。

| 解像度(steps=8) | 生成 | 事前チェックに残る時間 |
|---|---|---|
| 512 | 1.08s | 約3.9s |
| 640 | 1.80s | 約3.2s |
| 768 | 2.48s | 約2.5s |
| 1024 | 4.69s | 約0.3s(**予算外**) |

- **512〜768 はいずれも予算に収まる**。計画書 §4.2 の現行案(512〜768)は維持してよい。
- **1024 は使えない**。事前チェックの時間が残らない。
- 解像度の決定には、**語の判別率(E3)との突き合わせが必要**。速度だけなら 512 が有利だが、
  細部が潰れて事前チェックの通過率が落ちれば、やり直しが増えて逆に遅くなる。
  **この時点で解像度を確定させない**(計画書 §8-3 は未確定のまま)。

## この実験が答えていないこと

- **x0 予測が段階的か**(E1 の後半 / M1)。今回測ったのは時間だけで、中間フレームは
  まだ保存していない。蒸留の影響で序盤から鮮明すぎる可能性は未確認のまま。
- **語の判別率**(E3)。サンプル画像では 512px でも犬と猫が明瞭に描き分けられ、
  追いかける動作も見て取れたが、これは1プロンプトの印象であって測定ではない。
- **他プロセスと同居したときの速度**(計画書 §4.2)。今回は生成単独での数値。
  CLIP・VLM・LLM を載せた状態で測り直す必要がある。
