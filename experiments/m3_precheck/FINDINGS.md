# M3(E3・E5・ダミー生成)の結果と判断

計測日: 2026-10-16 / 生データ: `results/`
M2 が 512px で生成した28文の英訳画像を再利用。CLIP は `openai/clip-vit-base-patch32`、
VLM は `Qwen/Qwen3-VL-8B-Instruct`。

## 結論(先に書く)

- **512px は語の判別に耐える**。解像度の決定に付けていた条件をクリアした。
  4択での正解率は主語89%、目的語100%。
- **動詞のVLM確認は使える**。対照条件が当て推量ちょうどに落ちた(検証89% 対 対照25%)。
  自由入力の述語を許してよい。
- **事前チェックの閾値は、低め(マージン0)から始める**。上げると誤判定は減るが、
  語の差し替えが増えて減点が頻発する。

---

## 設計: 事前チェックの候補集合は、実際に出す4択と同じにする

CLIP のゼロショット分類に何を候補として渡すかが、事前チェックの性格を決める。
**実際にプレイヤーに出す4択をそのまま使う**ことにした。CLIP が4択から正解を選べないなら、
プレイヤーにも選べない見込みが高いので、通す意味がない。

### 「入力された語そのもの」で判定する

2026-10-16 に「ヒロオウミヘビがアオマダラウミヘビを追いかける」を試した。結果は3通りとも別々に壊れた。

| 入力 | 結果 |
|---|---|
| 日本語直入力 | ただのヘビ。海ですらなく土の上。2種の区別は消失 |
| 学名 `Laticauda semifasciata` | 足と嘴のある斑点の生き物と魚。まったく別物を捏造した |
| 英語通称 black-banded sea krait | ウミヘビは出るが1匹だけ |

重要なのは、**日本語直入力の絵は「ヘビ」としては立派**だということ。候補語に「ヘビ」を使えば
通ってしまうが、プレイヤーが4択から選ぶのは「ヒロオウミヘビ」なので、通してはいけない。
**候補集合は必ず入力語そのものを含む形で作る。**

## E3: 3語の判別(512px、28文)

| | 主語 | 目的語 |
|---|---|---|
| 4択での正解率 | **89%** | **100%** |
| 約50語のプールで1位 | 57% | 82% |
| 同3位以内 | 75% | 96% |

**512px で問題ない。** 解像度を上げる理由は見つからなかった。

### 目立つ対象に、目立たない語が潰される

4択を外した3件のうち2件は、**プール全体の1位が目的語**だった。

| 文 | 正解(主語) | プール1位 | 主語の順位 |
|---|---|---|---|
| 男性が犬を洗う | a man | **a dog** | 20位 |
| 少年が亀を追いかける | a boy | **a turtle** | 8位 |
| 赤ちゃんが積み木を積む | a baby | a teacher | 46位 |

CLIP の画像埋め込みは1枚を1ベクトルに潰すので、**画面で目立つ対象に引っ張られる**。
主語と目的語が1枚に写るこのゲームでは、目立たない側が構造的に不利になる。
主語の成績が目的語より悪いのは、おそらくこれが理由。

対策の候補(未検証): 領域を切り出して照合する、主語と目的語で別々の閾値を使う。
現時点では、主語の方が当てにくいという事実を受け入れる。

### 閾値のトレードオフ【現行案: マージン0で始める】

通過条件を「4択で正解が1位、かつマージン(1位−2位のスコア差)が閾値以上」とした場合。

主語(28件):

| 閾値 | 通過率 | 誤りを通した数 | 正しいのに弾いた数 |
|---|---|---|---|
| **0.000** | **89%** | 3 | 0 |
| 0.010 | 82% | 1 | 2 |
| 0.015 | 79% | 0 | 3 |
| 0.030 | 64% | 0 | 7 |

目的語は閾値0で100%通過、誤りゼロ。

**閾値を上げる誘惑に乗らないこと。** 弾かれた語は差し替えて再生成するので、

- 1ターンの待ち時間が増える(生成1.08秒がもう1回)
- プレイヤーの差し替え回数が増える。**4回目から減点**(RULES.md §6)

閾値0.030 にすると主語の36%が弾かれる計算で、数ターンで誰もが減点圏に入る。
**マージン0(=4択で1位なら通す)から始め、E7 で調整する。**

## E5: 動詞の確認(対照条件つき)

M2 で「VLM は常識で答えられる問いでは画像を見ていない」ことが分かったため、対照条件を置いた。

| 条件 | 見せた画像 | 正解を選んだ率 |
|---|---|---|
| 検証 | その文の画像 | **89%** |
| 対照 | **別の文の画像** | **25%** |
| | 当て推量 | 25% |

**対照がちょうど当て推量に落ちた。** VLM は画像を読んでいる。この確認方法は事前チェックに使える。

### E2 と E5 で結果が分かれた理由

| | E2(役割) | E5(動詞) |
|---|---|---|
| 問い | 犬が猫を追う / 猫が犬を追う | 4つの無関係な動作のどれか |
| 常識で答えられるか | **答えられる** | 答えられない |
| 結果 | 対照で破綻 | 対照が当て推量に落ちた |

**問いが常識で答えられるかどうかが分かれ目。** VLM判定を設計するときは、
「画像を見ずに答えられる問いになっていないか」を先に確かめる。

### 外した3件

| 文 | VLMの答え | |
|---|---|---|
| 警察官が泥棒を捕まえる | crossing | 絵に捕まえる動作が描かれていない(E2の所見と整合) |
| 鳥が魚をつかむ | holding | **grabbing と holding は意味が近すぎる** |
| 料理人がラーメンを作る | eating | 作る絵と食べる絵の区別が難しい |

## ダミー生成(RULES.md §5 の実装)

`dummies.py`。CLIP のテキスト埋め込みで正解との類似度を測り、
並べ替えた候補の中の位置で「近い/中くらい/遠い」の帯を切る。
**画像照合と同じ空間を使う**ので、「CLIP空間で近い」は「絵として紛らわしい」に対応する。

帯の幅が難易度のつまみ【現行案】。

| つまみ | 現行値 |
|---|---|
| 近い | 上位 0〜12% |
| 中くらい | 40〜60% |
| 遠い | 85〜100% |
| 類似語の上限 | 0.95(これ以上は正解になりうるとみなして除外) |

### 分かっている問題【要検証】

- **CLIP空間での近さが、絵としての紛らわしさと一致しない**(2026-10-16、M5の通し確認で判明)。
  「猫」に近い順を見ると、**ロボット(0.897)や車(0.895)がネズミ(0.890)より上**に来る。
  帯の切り方は設計どおり動くが、「近いダミー」が絵の上で紛らわしいとは限らない。
  難易度のつまみとしては粗い。E7 で正答までの時間を見ながら、
  画像埋め込み側での近さ(同じ語を描いた画像どうしの距離)を使う案も検討する。
- **動詞では類似度が 0.83〜0.90 に圧縮される**。主語・目的語ほど「近い/遠い」の区別が効かない。
  CLIP が動詞に弱いという計画書の指摘と整合する。
- そのため **類似語がダミーに混入する**。E5 で grabbing の4択に holding が入り、VLM が引っかかった。
  類似語の上限0.95は、動詞には緩すぎる。述語だけ別の上限にするか、
  手で類義語の対を禁止リストに持つ必要がある。
