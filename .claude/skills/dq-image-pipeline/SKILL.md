# Diffusion Quest 画像生成パイプライン スキル

## これは何か

このスキルは仕様そのものではなく**案内役**。詳細は `docs/noise_guess_game_plan.md` にある。
このゲームの肝は「ノイズから浮かび上がる過程」なので、**生成した最終画像ではなく、
途中のフレーム列が成果物**だと考えること。

## 外してはいけない原則

- **モデルは Z-Image-Turbo(Tongyi-MAI)で決定済み**【確定】。Apache 2.0。
  再検討するのは、計画書 §3.1 末尾に挙げた E1〜E3 の問題が出たときだけ。
- **NFE は `num_inference_steps` と同数**【実測 2026-10-16、E1】。HFモデルカードの
  「9を指定しても評価は8回」という説明は、diffusers の `ZImagePipeline` には当てはまらない。
  **取れる x0 予測は8枚に縛られない**。ただし Z-Image-Turbo は8ステップ前後に蒸留された
  モデルなので、増やして品質が保たれるかは未検証【要検証】。
- **x0 予測を順番に見せる方式は、M1 の実測で否定された**【実測 2026-10-16】。
  step0 の時点で何が描かれているか判別できてしまう(CLIP類似度 0.70〜0.86)。
  現在の有力案は**最終画像と初期ノイズの線形補間**(§3.3)。最終確認は E6。
  x0 予測を扱う場合は `x0_i = x_{i+1} - σ_{i+1}·v_i` で復元する(検算済み)。
  **途中の潜在変数をそのままデコードしてはいけない**(序盤がほぼノイズになる)。
- **最初のフレームを純ノイズにしない**。色や大まかな配置が見える状態から始める。
- **最後のフレームは回答開始から7秒までに出し切る**。9〜10秒に出すと、見てタップする時間が残らない。
- **ヒント(5.5秒)とフレーム切り替えを重ねない**。枚数や間隔を変えたら、5.5秒付近に
  切り替えが来ないか確認する。
- **見せる枚数は6〜7枚が目安**【現行案】。類似度曲線を等間隔に区切って選び、序盤の色の塊と
  終盤のほぼ同じ画像を間引く。
- **解像度は512×512で確定**【確定 2026-10-16】。企画者がスピード重視で決めた。
  実測は512が1.08秒、640が1.80秒、768が2.48秒、1024は4.69秒で予算外(いずれも8ステップ)。
  **勝手に上げない。** ただし細部が潰れて語の判別率が落ちるリスクは残るので、
  E3で512での事前チェック通過率を測り、低ければ報告して判断を仰ぐ。
- **画像生成を最優先**。同じGPU(RTX 6000 Ada 48GB)に CLIP・VLM・LLM が同居するため、
  互いに遅くなる。生成より重い処理を割り込ませない。

## 蒸留モデルの落とし穴(実測で確認済み)

懸念は当たった。Z-Image-Turbo は DMD 系の蒸留モデルで、**step0 の x0 予測がすでに判別可能**。
`get_default_z_image_sigmas(n) = linspace(1.0, 1/n, n)` のため step0 は必ず σ=1 からの
一発推定で、**ステップを増やしても最初のフレームは曖昧にならない**。

代替案の現状。

1. **線形補間(有力)**: 最終画像と初期ノイズを画素空間で補間する。α=0.17 でかすかに輪郭、
   α=0.33 で判別可能。α の配り方が難易度のつまみになり、枚数も NFE に縛られない。E6 で確定。
2. **Z-Image-Base**: `Tongyi-MAI/Z-Image` として実在するが、28〜50ステップ・CFG 3〜5 が推奨で、
   概算8秒以上。**予算外**。

**LPIPS だけで判断しないこと。** LPIPS は「まだぼやけているか」を測るので段階的に見えるが、
ゲームで問題になるのは「何が写っているか分かるか」で、そちらは CLIP 類似度に近い。
M1 では両者が食い違い、LPIPS だけ見ていたら見誤っていた。

## 報告値と実測値を混ぜない

計画書の「RTX 4090で1024×1024を約2.3秒」は**サードパーティの報告値**で、この環境の性能ではない。
実際、この環境の実測は同条件で4.69秒と約2倍だった。実測値は
`experiments/e1_generation_speed/FINDINGS.md` にある。

- 文書やコメントに書くときは「報告値」と明記する。
- 実測したら、**解像度・バッチ・同居プロセスの条件と一緒に** `experiments/` に記録する。
  条件のない数値は役に立たない。

## 日本語の扱い【要検証】

- Z-Image-Turbo の公式対応言語は英語と中国語。**英訳を前提に設計する**。
- ただしテキストエンコーダは Qwen3(4B)で多言語モデルなので、日本語がある程度通る可能性は残る。
  E4 で「日本語直入力」と「英訳」を比べる。直入力が使えれば翻訳工程の待ち時間を省ける。
- 同音異義語(橋/箸、紙/神)は、**他の2語の文脈を見て訳を決める**。
- **選択肢の表示は日本語のまま**。内部の照合は英語で行う。
- 破綻を見つけたら、原因が英訳かモデルかを切り分ける。**英訳の結果は必ずログに残す**。
