# Diffusion Quest リアルタイム同期 スキル

## これは何か

このスキルは**案内役**。構成は `docs/noise_guess_game_plan.md` §4.1〜4.4、
公平性のルールは `RULES.md` §8 にある。実装の前に両方を読むこと。

**このゲームは早押しなので、同期と判定は「機能」ではなく「ルールの一部」。**
実装の都合で崩さないこと。

## 使い方

| タスクの内容 | 読むべき箇所 |
|---|---|
| 全体構成(クライアント / サーバー / GPU) | 計画書 §4.1 全体像 |
| 配信と先読み、時刻同期 | 計画書 §4.3 同期と配信 / RULES.md §8 |
| 工程ごとの時間の予算 | 計画書 §4.4 |
| フェイズの秒数と回答中のタイムライン | RULES.md §2.1, §2.2 |
| 先着判定と得点 | RULES.md §4.3 |
| GPU の同時実行と順番待ち | 計画書 §4.2 使用GPU |
| 通信遅延による不公平 | 計画書 §7 のリスク表 |

## 外してはいけない原則

- **先着・正誤の判定はサーバー側で、受信時刻を基準に行う**。クライアントが申告した時刻を
  信用しない。クライアント側で正誤を判定して結果だけ送る実装にしない。
- **フレームは全枚数を生成し、事前チェックを通してから配信する**。生成しながら1枚ずつ
  流してはいけない(事前チェックができなくなり、絵に出ない語を弾けなくなる)。
- **選んだフレームは、回答開始前に全員の端末へ先読みさせる**。回答中に読み込ませない。
- **「回答開始の時刻」をサーバー時刻で全員に伝え**、各端末がその時刻に合わせてフレーム切り替えと
  ヒント表示を行う。サーバーから「今切り替えろ」と都度送る方式にしない。通信の遅い人だけ
  画像が遅れる不公平が出る。
- **時間切れの人には、そのターンの画像と選択肢を配信しない**【確定】。クライアント側で
  隠すのではなく、**サーバーが送らない**。
- **入力フェイズは、3人全員が入力したら即終了**する。10秒を待たない。
- **選択肢の位置は10秒間固定**。消える選択肢は詰めずにグレーアウト(位置が動くとタップが遅れる)。

## タイマーの基準

| フェイズ | 長さ | 備考 |
|---|---|---|
| 入力 | 10秒 | 全員が入力したら即終了 |
| 生成 + 事前チェック | 5秒以内【現行案】 | 超過時は VLM チェックを省略する経路あり |
| 回答 | 10秒 | ヒントは開始から5.5秒、最終フレームは7秒まで |
| 結果表示 | 5秒前後【現行案】 | |

回答フェイズ内の詳細なタイムラインは `RULES.md` §2.2。**ヒント(5.5秒)とフレーム切り替えが
重ならないようにずらす**こと。

## GPU の制約

- GPU は1台(RTX 6000 Ada, 48GB)。画像生成・CLIP・VLM・ダミー生成用 LLM が同居する。
- **画像生成を最優先**にする。VLM の動詞チェックには時間上限を設け、超えたら省略する。
- **1台で同時に処理できる生成は限られる**。複数グループが同時に遊ぶと生成が順番待ちになる。
  **試作では1グループずつの利用を前提**にする【現行案】。複数グループの同時対応を
  勝手に作り込まない(計画書 §8-15 で未確定)。
- 並行実行による速度低下は**実測が必要**【要検証】。並行数を計測して調整する。

## 未決定の項目

実装で必要になったら、自己判断せず人間に確認する(`RULES.md` §11)。

- 同時刻に複数人の回答が届いた場合の扱い。
- 回答フェイズ中の切断・再接続の扱い。
- ゲーム途中で1人が抜けた場合の扱い(3人固定のため規定がない)。
