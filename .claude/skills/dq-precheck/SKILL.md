# Diffusion Quest 事前チェック スキル

## これは何か

このスキルは**案内役**。手順の詳細は `docs/noise_guess_game_plan.md` §3.4、
減点ルールは `RULES.md` §6 にある。実装の前に両方を読むこと。

## なぜ必須なのか(削ってはいけない理由)

事前チェックがないと、**「絵に出ない語を入れた人が有利になる」ゲームになる**。

得点が「最初に正解した人」だけに入る設計では、絵に出ない語を入れた人は、自分の語を
当てられる心配をせずに残り2語を当てれば先着できる。このため事前チェックは
**必須の仕組み**として扱う【確定】。「とりあえず無効化して先に進む」をしないこと。

## 手順(計画書 §3.4 の要約)

1. **CLIP のゼロショット分類**で、3語それぞれが候補語の中で上位に来るかを確認する。
2. **述語(動詞)は CLIP が苦手**なので、VLM に「この画像で何が何をしていますか」と尋ね、
   入力語と一致するかを見る。
3. 通らない語は、システムが補完した別の語に**差し替えて再生成**する【確定】。
4. 補完する語は、**過去に事前チェックを通った語のプール**から同カテゴリで引く【現行案】。
5. **やり直しは1回まで**。それでも通らなければターンを無効にしてやり直す【現行案】。

## 外してはいけない原則

- **CLIP に動詞の判定をさせない**。動作の判別は苦手で、述語担当だけが不当に落ちる。
  動詞は VLM で確認する。
- **VLM チェックには時間上限を設ける**。待ち時間が予算(生成と合わせて5秒)を超えそうな場合は、
  **VLM チェックを省略する経路**を用意する。CLIP チェックは省略しない。
- **語を差し替えられた人は、ゲーム中3回目までは何も起きない**【確定】。4回目以降のみ減点。
  減点はそのラウンドの得点から1点で、**0未満にはしない**【現行案】。
  差し替え回数は**ゲーム単位**で数える(ラウンドごとにリセットしない)。
- **この3回の猶予を削らない**。動詞の判定は特に誤りやすく、描けているのに不合格とされた人が
  減点される事故への緩衝になっている。
- **閾値は実測してから決める**【要検証】。CLIP の上位判定も、VLM の一致判定も、先に数値を
  決め打ちしない。E3(3語の判別)と E5(動詞の描画)の結果を見て決める。
- **入力フィルタと出力画像のセーフティチェックの両方をかける**【現行案】。片方だけにしない。
- **入力時の警告は出すが、入力は弾かない**【確定】。「絵にしにくいかもしれません」と伝えるだけ。

## VLM判定の罠(M2で実証済み)

**VLM は、常識で答えられる問いでは画像を見ていない。** M2(E2)で2方式を試し、両方とも
対照条件で無効と分かった。

- 画像1枚ずつ「犬が猫を追う / 猫が犬を追う」の2択 → **常識**で答えてしまい、
  正順の絵と入れ替えの絵に同じ答えを返した(13組中12組)。
- 2枚を並べて「役割が入れ替わっているか」 → **絵が違えば**「入れ替わっている」と答えた。
  役割が同じはずの対照(日本語版 vs 英訳版)でも 10/13 が「入れ替わっている」。

**動詞の一致確認(「この画像で何が何をしていますか」)も、常識で答えられる問い**なので
同じ罠にかかる。E5 では必ず**対照条件**を置いて、判定が画像に反応しているかを確かめること。

一方、「画像に文字が写っているか」のような**常識の入り込む余地がない問い**では使えている。
問いの性質で使い分ける。

## 実装の罠

transformers 5.x の `CLIPModel.get_image_features` は**テンソルではなく `ModelOutput` を返す**。
射影済みの埋め込みは `pooler_output` に入っている。M1 でここを踏んだ。

## 時間の予算

生成と事前チェックを**合わせて5秒以内**が目標【現行案】。最も重くなりやすいのは VLM と LLM の
呼び出し。この経路にコードを足すときは、**追加分の実測時間を必ず測る**。

やり直し回数の上限(現行案は1回)は、待ち時間の予算に収まらなければ見直す対象。
上限を変えるときは `RULES.md` §6 と計画書 §8-13 も一緒に直す。
